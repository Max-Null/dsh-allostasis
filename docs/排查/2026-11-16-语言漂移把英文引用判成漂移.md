# 语言漂移把中文思考里的英文引用判成漂移

> 状态：**已修** · 2026-11-16 · 判据改了 `src/drift.ts`，口径同 `tools/analyze-thinking-lang.mjs`
> 触发：中文思考里引用一段英文文档（技能描述、README、报错原文）后，收到「语言漂移提醒（应变）」。
> 结论：**密度单独一项分不开「我在用英文思考」与「我抄了一段英文」。** 中文思考的英文词总量本来就小，一段引用就足以把密度顶过 0.15。
> 口径：本机 `sessions-ssid` 下 112 个会话文件（zstd 多帧，逐帧解压），共 **9,651 条** `assistant/message` 的 reasoning 原文，逐条重算新旧两版判定。

## 一、误判长什么样

会话 `session-2b54854d`，turn 1 step 1，判据给出密度 **0.16**、**61** 个英文词。原文是整段中文推理（自由复述）：

```
用户问的是一个产品/技术设想：……他问：二者结合是不是能做一个「免费版 DSH plan 模式」？
先理解「plan 模式」指什么——……
另外考虑是否要用 dsh-doc 或 official-plugins 技能。用户问的是插件能力，属于「Check DSH's
optional plugins when the user asks how to do or use something in this app, whether it can, ...」
但这里是讨论自造插件设想，偏开发。不过先查工作区实际插件更直接。
```

61 个英文词里约 40 个集中在被引号包住的那一句技能描述上，功能词（`the` / `is` / `when` / `to` / `in` / `this` / `it` / `can` / `or` / `should` …）也几乎全来自它。主体行文一字未变是中文。

## 二、为什么 0.15 这么容易被撬动

密度是**比例**：中文思考的英文词分母本来就小（实测 51–250），而一段被抄进来的英文描述能贡献 8–15 个功能词。分子的绝对量没变，分母也没变大多少，比例就过线了。

旧判据里唯一的抗噪手段是「英文词数 ≥ 50」，但它挡的是**太短**的样本，挡不住「刚好够长、内容大半是引用」的样本——后者恰恰是中文思考引文档的典型形态。

## 三、两类样本的分界

拿全部 9,651 条思考，按「中文字数 / 英文词数」看两群：

| 群 | 比值范围 |
|---|---|
| 中文思考被误判 | **≥ 1.47**（多数 5–60） |
| 真英文漂移 | **≤ 0.53** |

中间没有样本。所以「汉字比英文词多」这个条件单独就足以分开两群，而且它不依赖引用有没有加标记。

## 四、修法：三层，都做在度量侧

阈值 0.15、门槛 50、`driftThreshold` 配置项都没动，改的是「哪些文本与哪些词算进分母」。

1. **剥离明确标出的引用区**（`stripQuotations`）：围栏代码块、行内代码、`「」` `『』` `“”` `""` 内的内容整段替换为空白。
2. **只算自然语言词**（`naturalWords`）：排除单字母、全大写缩写（`API`）、含中间大写的驼峰名（`readSurface`）；下划线与数字由词形正则直接切断。它们证明「在读代码」，不证明「在用英文思考」。
3. **中文兜底**（`verdict`）：汉字数 ≥ 英文词数时直接判 `chinese`，不看密度。这一层管住**没加引号**的整段英文粘贴，剥离规则够不着它。

单引号刻意不剥：英文行文里的缩写（`doesn't`）会连带被删，那是在删正文。

## 五、复核

| 指标 | 旧判据 | 新判据 |
|---|---|---|
| 判为漂移的步数 | 150 | **28** |
| 其中主体是中文（误判） | 122（81%） | **0** |
| 旧中文判成新漂移（新增误报） | — | **0** |

保留下来的 28 步全部是英文主体：汉字/英文词比 ≤ 0.53，其中 11 步汉字为 0。修复掉的 122 步里，`w < 50`（剥离后样本不足）与 `cjk ≥ w`（中文兜底）大致各半。

复现：解压会话后跑 `tools/analyze-thinking-lang.mjs`；工具已改为同一口径，并支持 v4 的 `message.content` reasoning 块。

## 六、遗留边界

- **无引号、中文又少的整段英文粘贴**：第三层按汉字数判定，若中文本身也少于英文词数，仍会判漂移。实测样本里没有出现——真按这种形态思考时，它离「确实在用英文思考」已经很近。
- **剥离后掉到 50 词以下**：短英文思考更容易落进 `insufficient`，即漏判。这是刻意取舍：提醒是纠偏信号，误报的代价（打断正常中文思考）大于漏报。
- **引用区识别只看标记**：缩进代码块、无引号的整段引用一律靠第三层兜底，不做启发式猜测。
