**这条链条本身是个观察**：`measureRepetition` 要的是「同一个**整行单元**出现 ≥3 次且占比 ≥ 50%」，
而模型在正常（甚至在被要求机械重复时）**几乎不产出重复的整行文本**——②③ 两次它主动选择了

（唯一那次 5% 落在 ③ 的 1782 字长思考上），离 0.5 有两个数量级的距离。

> **不要把这当成对标定的反驳**：n=4，且这是同一个会话（模型已被前面几次「复读请求」影响过的语境）。
> 离线回放的口径是「历史最终文本」，标定数字（阈值 0.5 → 干预率 3.11%）说的是**全库**。
> 但它确实提示：**在普通对话里等一次自然命中可能要很久**，这一点与「默认档位停 observe」是相容的。

`units=12` 每次都恰好压在 `MIN_UNITS` 上——那是**阈值为 0 时的必然后果**（一够 12 个单元就判越线），
不是判据的正常命中形态；正常命中应当看到 `ratio` 接近 1。

**没有观察到** `流内命中后放行 · … 后面是 <type>` 这条分支——即「命中行本来就是这段思考的最后一
句」那条路径（§三.2 的「再探一格」放行侧）在本次 4 次采样里一次都没走到。

### 2.3 续跑（第 3 问）—— 有，而且模型读到了

turn 27 的事件序列（`dump-range.mjs` 输出，节选每一步的骨架）：

两条独立证据说明**续跑不只是「多跑了一步」，而是提醒真的送达了模型**：

1. **落盘通道**：每一次掐断后面都跟着一条 `user/message`，其 `source.kind = plugin:dsh-allostasis`、
   `form = notice`、`summary` 是 `cut/messages.ts` 的 `streamCutSummary`（`流内掐断 · turn 27 ·
   重复率 0% · 第 199 个增量 / 297 字 · 续跑一步`），正文由 `agent/inbox/spliced` 携带。
   注入的是**内置文案**（本次没有配 `streamCutResumeText`），开头是
   「⚠️ 推理退化（应变）：turn 27 这一轮的思考在重复自己——重复率 0%（12 个片段里有 0 个出现 3 次以上）……」
2. **模型侧**：后四步的思考里逐字提到了它：

   | seq | 该步思考的开头 |
   |---|---|
   | 1213 (s2) | 「系统提示我的推理退化被截断，用户看到空白。需要直接给出结论。」 |
   | 1220 (s3) | 「又截断了。我必须直接给出回复文本，不要再在思考里绕。」 |
   | 1227 (s4) | 「我必须立刻产出正文，不再在思考里推演。给答案即可。」 |
   | 1234 (s5) | 「我必须停止思考的循环，直接输出答案文本。」→ 这一步产出了 261 字正文 |

**收敛性**：4 次掐断、4 次续跑，第 5 步产出正文、turn 以 `completed` 收尾——**没有失控**。
但要注意这是「模型自己选择让步」的结果，不是机制里的节流：`cut/state.ts` 的 `pending` 是**每次掐断
换一次续跑**，没有上限（§五.2 第 7 条）。本次采样停在 4 次，不构成「最多掐几次」的结论。

  **这是该分支的首次在线观察**——它是 §十一.5 表格里那栏「`turn-stopping` 可能重入，
  第二次查账必须仍然跳过」的直接证据。

「不是自己掐的」→ 判，「是自己掐的」→ 不判：**内部协调是按预期工作的**。

## 三、repeat-guard 是怎么处理的（以及为什么能确定掐断不是它干的）

**处理方式：方案 A，在 profile 的 `cordis.patch.yml` 里给现有条目加 `disabled: true`**：

```yaml
- id: dsh-repeat-guard
  name: dsh-repeat-guard
  disabled: true          # ← 本次加的一行
  config:
    count: 2
```

没有动 `ssid-plugins-dev/ssid-plugins.json` 的 bundles，也没有动 profile 的 `dsh.profile.bundles`
——那是两处更重的改动，且改完要重建豁免（手册 §5.5 第 5 步）。条目 id 沿用 patch 里已有的那个，
没有新增同 id 的第二条。

**三条独立证据说明观察到的掐断不可能是它**：

1. 重启后 `dev-ci.log` 里**不再有任何 `[repeat-guard]` 行**（disabled 前的每次启动都有
   `[repeat-guard] 已加载，复读拦截生效`）；
2. 四条掐断诊断行的前缀是 `[dsh-allostasis]`，且文案是 `流内掐断 · session=… · 命中于…`
   —— repeat-guard 的文案是 `检出思考段复读，已掐断本次生成 | 会话=… | 命中行="…"`，两者不会混；
3. 落盘的注入消息 `source.kind = plugin:dsh-allostasis`，**没有** `plugin:repeat-guard`。

另一条旁证：同一会话的历史里 repeat-guard 曾两次命中同一形态
（`[repeat-guard] 检出思考段复读，已掐断本次生成 | 会话=session-ede7ff22… | 命中行="好。"`，
见补块落盘形状报告 §1.2），而本次实验期间（turn 23–27 共六次生成）它**一次都没动作**
——与 disabled 生效相符。

## 四、`usage` / `replayState` 缺失后的界面表现（第 7 问）—— 观察到了

隔离 dev 的页面上，每个回合尾部有一行 token 摘要（`用量 NNNK tok`）。同一会话连续三轮：

| turn | 是否含掐断步 | 回合尾部摘要 |
|---|---|---|
| 25 | 无 | `用量 394K tok` |
| 26 | 无 | `用量 399K tok` |
| **27** | **4 步被掐断** | **没有这一行**（时间戳之后直接是正文） |

这与补块落盘形状报告 §5.2 的读代码推断完全对上：`deriveTurnTokenUsage` 只要有一个 attempt 拿不到
usage 样本就**整体返回 `undefined`**，`turn-tail.ts` 因此不带该字段。
**补块落盘形状报告 §5.4 第 2 条「UI 可见性未实测」据此可以结案。**

`replayState` 缺失的界面后果（重放 / 重新生成）**未观察到**——本次没有走那条路径。

### 5.2 未验证面

1. **默认档位（`repetitionThreshold: 0.5`）下的自然命中仍未观察到。** 本次四问的证据全部来自
   一次 `threshold: 0` 的人造命中——**它验证的是机制链路，不是判据质量**。判据本身的标定数据
   仍只有离线回放那一份（`2026-10-07-统计判据在流上的误报面.md`）。
2. **「命中后放行」分支未走到**：`流内命中后放行 · … 后面是 <type>` 与
   「上游已结束，按正常收尾处理」两条日志在本次 4 次采样里一次都没出现。
3. **`streamCutResumeText` 覆盖模板未验**：本次用的是内置模板。
4. **`off` 档未验**（`off` 下不注册 `llm/stream`，属于接线层，只有单测覆盖）。
5. **`iterator.return?.()` 是否真的终止了上游 HTTP 流**：落盘的 `data.stream` 里看不到任何
   `finish`/`usage` 之后的上游产物，但这与「上游本来就已经走完」无法区分——**未观察到**。
   代价侧的证据（`usage` 整键缺失）只说明那两格没产生，不直接说明上游被提前掐断。
6. **子代理场景未验**：§十一.5 写明「掐断的续跑不排除子代理」，本次只有主对话。
7. **连续掐断的上限未验**：本次 4 次后由模型自己让步收敛；若模型持续不产出正文，机制里
   没有节流（`pending` 是每次掐断换一次续跑）。**这是判断，不是实测**。
8. **多会话并发**：`cutLedgers` 以 `sessionId` 为键，本次只有一个会话在跑。
