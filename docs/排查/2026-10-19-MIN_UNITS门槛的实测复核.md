# MIN_UNITS=12 仍然成立：517 条判定的实测复核

> 状态：**结论已定 · 不改判据** · 2026-10-19
> 触发：给 `autoCompact` 做验证时注意到一条 `units=9 ratio=56%` 被判成 `insufficient`——重复率过半却被放过，怀疑门槛把真实退化一起挡掉了。
> 结论：**不改。** loop 从未在 `units < 12` 时出现（最小 16），而被漏掉的「高重复短样本」在 517 条去重样本里只有 3 条（0.6%）。
> 口径：`host.log` 里全部 `repetition=<verdict> units=N ratio=M%` 行，按「判定 + units + ratio」去重（同一 turn 会因热加载等因素重复打印，原始 2228 条去重后 517 条）。

## 一、数据

| 结论 | 条数 |
|---|---|
| normal | 439 |
| loop | 55 |
| insufficient | 23 |

| 观察 | 读数 |
|---|---|
| loop 的 units 范围 | **16–245**（最小 16，高于门槛 12） |
| normal 的 units 范围 | 12–1739 |
| insufficient 里 `ratio ≥ 50%` | **3 条**（units 9 / 11 / 8，ratio 56 / 55 / 50） |
| insufficient 里 `ratio < 10%` | 11 条（真正的短样本、低重复） |

## 二、为什么不改

1. **门槛不紧**：loop 的最小 units 是 16，说明真实退化一旦发生，样本长度普遍远超 12。这个数卡在边界下方，不是边界上。
2. **漏检面极小**：3 条对 55 条 loop，补上它们把召回从 94.8% 推到 100%，但代价是同时把 11 条「短且不重复」的样本纳入判定视野——误报面的量级反超收益。
3. **那 3 条是擦边不是明显漏检**：ratio 落在 50–56%，正好贴着阈值，本身就处在噪声区。

## 三、将来若要动这个门槛，先看这三条

- **别只挪阈值**：下调 `MIN_UNITS` 会同时改变长样本以外的所有判定；本次 11 条 `ratio < 10%` 的短样本就是被连带风险的代表。
- **要处理短样本就单开判据**：例如「`units < 12` 且 `ratio ≥ 0.7`」单独命中，与现有阈值互不干扰。
- **误报面的实测口径**见 `2026-10-07-统计判据在流上的误报面.md`；流层面的复现用 `tools/audit-stream-firing.mjs`，本文这份是日志层面的统计。

## 四、这份数据还有个副产品

55 条 loop 的 units 普遍远高于门槛（16–245），说明现在被抓住的退化都是「长段复读」而不是边角情况。这直接支撑了 `autoCompact` 的设计前提：一旦触发，作用对象是足够长的脏历史，压缩有东西可压。
