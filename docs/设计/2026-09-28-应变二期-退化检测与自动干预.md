# 应变二期：退化检测与自动干预

> 状态：**方案（待审）** · 2026-09-28
> 前置：`2026-09-20-应变-设计方案.md`（一期，中文锚定已上线）；本期的证据基础是
> `docs/排查/2026-09-28-推理退化与上下文占用脱钩.md`（19 轮会话实测）。
> 触发场景：用户观察到「思考莫名停住，追问也继续停，只当是思灵坏了」——两次观察都发生在
> 上下文占用很低的时刻（37% / 26%），而系统对此没有任何表示。

## 一、要解决什么

用户侧的现象是三件事叠在一起：

| 现象 | 用户的解释 | 实际 |
|---|---|---|
| 思考突然停住 | 思灵坏了 | 模型推理塌成单字循环后自行收尾 |
| 追问还是停 | 更确信坏了 | 追问只增加轮次，不改变上下文里的退化样本 |
| 不知道该做什么 | —— | 压缩可以打断，但没有人知道，也没有入口 |

所以本期要补的不是一个诊断，是**三件产品的缺失**：**预警**（让用户知道在发生什么）、
**兜底**（自动打断）、**透明**（事后能看见系统做了什么）。

## 二、机制假设（有证据，但未定因）

实测把三次观察拼成了同一个机制：**退化自我强化**。

1. 模型开始输出 `好` / `做` / `我发` 这类无信息的碎片
2. **碎片留在上下文里**，成为最近距离的样本
3. 下一步生成被自己的碎片诱导，继续输出同类
4. 样本越滚越多 → 循环持续

支持它的三处观察：

- **追问无效**：追问不减少任何碎片，循环照跑（用户实测）
- **浅压缩无效**：压到 23.9% 后，高频碎片 `好×49 做×32` 与压缩前**逐字相同**——样本还在
- **深压缩有效**：压到 6.0% 后重复率**归零**，碎片消失——样本被清出上下文

**未验证的推论**：既然关键是「样本在不在」，那么**只压掉含退化样本的那一小段**就该够，
不必压到某个绝对深度。第二次压缩压到 6% 有效，可能只是顺带扫走了样本，而非 6% 这个数字
本身有效力。**这是本期第一个要验的假说**（见 §六）。

### 3.1 为什么是 `compactRegion` 而不是 `compactNow`

一期的 §5.1 判定「自己压缩自己逻辑上不成立」，理由是 `compactNow` 走 `runMaintenance`、
要求 agent idle、且与 turn 互斥——结论对 `compactNow` 成立，但**本期不用它**。

`CompactionEngine` 上还有第三个 API（`compaction/src/index.ts:187`）：

```ts
abstract compactRegion(
  start: SessionSeq,
  end: SessionSeq,
  agent: CompactionAgentContext,   // 只有 session + options，无 runMaintenance
  signal?: AbortSignal,
): Promise<CompactionResult>
```

两个差别决定了它可用：

- **不要求 idle**。参数类型是 `CompactionAgentContext`（`session` + `options`），不含
  `runMaintenance`，所以**在 `agent/pre-step` 里可以直接调用**。§5.1 列出的四样复杂度
  （竞态、幂等、有界重试、异常兜底）随之消失。
- **区间由调用方给**。`compactIfNeeded` 与 `compactNow` 都自己选区间；`compactRegion`
  接受 `start`/`end`，这是「只压退化样本」得以成立的前提。

`compaction-basic` 已实现它（`index.ts:358`），且**它自己的自动路径就在调它**
（`compactIfNeeded` 在 `index.ts:301`、`338` 两处转发）。

### 3.2 `compactRegion` 的约束

- **平衡边界**：`start` / `end` 不能把同一个 step 的 tool-call / tool-result 对拆开
  （`region.ts:350,354`）。选区间时用 `toolPairingBalancedBefore` / `toolPairingBalancedAfter` 对齐。
- **区间必须存在于 surface 上**（`region.ts:341,342`），且 start 不晚于 end。
- **必须在 turn 内**：`region.ts:199` —— `automatic compaction events must be enclosed in a turn`。
  在 `agent/pre-step` 调用满足这一条。
- **同一 session 不能并发压缩**（已有 `compaction/start` 标记作为锁）。

### 3.3 失败路径（实现前必须定）

`compactRegion` 会抛：并发压缩（已有事务）、区间不存在或不平衡、摘要请求失败、提交阶段失败。它被调用的位置是 `agent/pre-step`，**那是个 waterfall handler**——异常向上传播会威胁整个 turn。

所以有一条硬要求：**压缩整段包在 try/catch 里，失败时降级为「只记录、不压缩」**。绝不能把一个辅助判据的失败变成 turn 的失败。**判定与动作必须解耦**：判定可以在任何一轮失败，动作只是可选的后继。

另外两条待定：

- **压缩期间的 surface 归属**：`compactRegion` 是异步且耗时的，要确认它不会与紧随其后的 step 抢同一段 surface。
- **冷却**：压缩后判据若仍成立（碎片未必一次清干净），不能立刻再压。冷却期是必需品而非优化项，间隔取值待 §六.4。

## 四、判据

### 4.1 形态

与一期中文锚定同构，**新增一个纯函数**：

```
重复率 = 单条推理按换行与中英句读切分后，出现 ≥3 次的单元占全部单元的比例
触发   = 重复率 ≥ 阈值 且 连续 N 步成立
```

**连续 N 步是必要的**：单次抖动在正常期也会出现（实测正常期峰值 35%），一旦按单步触发，
节流之外还要多一层误判防线。

### 4.2 起点取中间值

**不采用拍脑袋的偏好值，取实测隔离带的中点。**

同一会话（`session-fabc21b2`，19 轮）的分布：

| 群 | 重复率区间 | 样本 |
|---|---|---|
| 正常期 | 0% – 35% | t1 0%、t19 0–6%、t20 28%、t21 17%、t2 31%、t3 35% |
| 退化期 | 48% – 92% | t10–t18 的 18 个采样，最低 48%、最高 92% |

隔离带 35% – 48%，**起点取 50%**，连续步数取 **2**。

**为什么不是隔离带中点 41.5%**：48% 那个采样（t10/s45）紧邻的前后是 64%、64%、78%，它本身大概率已在退化中，不宜当作正常期上界。按更干净的两端算（正常期 35%、退化期主体 68–92%），中点落在 51.5%。

**连续 2 步的代价是延迟，要写进判据的账里**：按同一份数据回放，触发会落在 t11/s2 而不是 t10/s44——中间夹了一个 48%（低于阈值，计数重置）。**晚约 3 步**。这是「宁可晚一点也别误报」的取舍，不是免费的。

**这是一份单会话样本，不是标定结果**——它的作用是给第一期一个可用的、有依据的起点，
而不是宣称 50% 是对的。标定需要 §5 的数据。

### 4.3 判据要可复盘

阈值调整的依据必须能事后重建，所以**判定输入必须可重放**：

- **推理文本已在会话日志里**（`reasoning-chunks.texts`）→ 重复率可离线重算
- **每一轮的占用与压缩点已在日志里**（`data.usage` / `compaction/start`）
- 因此「如果当时阈值是 X 会怎样」可以离线回答，**不需要插件额外落盘**

**缺口**：插件**实际**用过的阈值与判定结果不在日志里。若只靠重算，复盘的是「按当前
脚本判会怎样」，不是「插件当时判了什么」。两个选择：

- **A（推荐）**：触发时 append 一条会话事件（`SessionEventMap` 是 merge-extensible 的），
  记录 `{重复率, 连续步数, 阈值, 区间, 结果}`。有影响的行为本就该留事件。
- **B**：只做重算，不落事件。省一条事件，但复盘口径与线上口径可能漂移。

## 五、阈值不是一个常数（承接一期 §六）

一期已论证「固定阈值站不住」（§2.2），并给出推进节奏：**第一期固定阈值并采集数据，
第二期标定任务类型 → 设定点的映射**。本期就是那个第二期的前半段。

### 5.1 三条并行的路

| 路 | 做法 | 代价 |
|---|---|---|
| **显性配置项** | 阈值与连续步数进 `Config`，可在 `cordis.patch.yml` 改 | 零新增机制；本工作区遵循 DSH 插件规范「No hardcoded tunables in plugins」（`deepseek-harness/AGENTS.md`）|
| **数据积累** | 用 §4.3 的可重放数据标定 | 需要样本量；跨会话扫已有工具 |
| **LLM 自调** | 由模型在运行时调整设定点 | 见 §5.2，有结构性风险 |

**前两条没有争议，本期一起做**。第三条需要约束。

### 5.2 LLM 自调：可行，但必须设边界

**结构性风险**：被判定的对象参与制定判定标准——模型可能把阈值调到永不触发（少被打断），
也可能反过来过度激进。这与「被监控者调监控灵敏度」是同一个问题。

**可接受的形态**是在它之上加三条约束：

1. **调的是设定点，不是开关**。可调范围有界（例如 `[0.4, 0.7]`），不允许关掉检测。
2. **调整必须留痕**。每次改动进会话事件，可审计、可回退。
3. **调整要有依据**。输入是 §4.3 的重放数据，不是模型的当场感受——「这次是误报」这类
   自述不能单独作为依据（模型在退化时正是不可靠的一方）。

在满足这三条之前，**LLM 自调留作二期后半段的候选**，不阻塞前半段。

## 六、待验证清单

1. **只压一小段够不够打断循环？**（§二 的推论）—— 这是本期最关键的未知。
   验证方式：下一次退化发生时，只压含退化样本的那几轮，观察后续重复率。
2. **退化样本的准确定位**：是「所有输出了高频碎片的 assistant 节点」，还是「最近的 N 个节点」？
   压缩区间怎么选，取决于这个答案。
3. **阈值 50% / 连续 2 步的实测误报率**：需要 >= 3 个不同形态的会话样本。
4. **压缩后是否复发**：深压缩那次打断了循环，但样本只有一次。复发间隔决定「自动干预」
   要不要配一个冷却期。
5. **`compactRegion` 在 `agent/pre-step` 内的实际行为**：约束（平衡边界、turn 内、无并发）
   都来自源码阅读，**尚未实机跑过**。
6. **能否只清历史推理、不动对话？** `assistant` 的 `reasoning` 会被序列化成 `thinking` block
   回传给模型（`llm-deepseek/src/serialize.ts:26-38`），所以碎片确实在上下文里。反过来——
   **只去掉历史推理块、保留全部对话与工具结果**，是否同样能打断循环？这条路若成立，代价
   比压缩小得多（推理本就不是交付内容）。已知障碍：DeepSeek 要求推理带 `signature` 回传，
   缺签名会走 `onReplayDegrade`；**清掉整块推理是否被 provider 接受、是否损伤质量，都未验证**。

## 七、留档与透明

**「留档」在这里要分三层，别混在一起**：

| 诉求 | 现状 | 本期动作 |
|---|---|---|
| 保住原始数据 | **已满足**：压缩是遮蔽不是删除，`shadowedSeqs` 是日志索引，`/export` 可导出可读格式 | 不做 |
| 让用户知道系统做了什么 | 无 | **触发时给一条用户可见记录** |
| 保住「什么重要、为什么重要」 | 无 | 见下 §7.2 |

### 7.1 留档救不了误判

`CompactionEngine` 的公开接口（`compactIfNeeded` / `compactNow` / `compactRegion`）里**没有撤销操作**，压了就是压了，模型再也看不到那段内容。（surface 结构上允许再替换一次，但那要求插件自己构造替换区间，不在本期范围。）所以**对冲误判不能靠
存原文**，只能靠：

- 判据保守（§4.2 的连续步数）
- **压得少**（`compactRegion` 只压相关区间，误判代价从「丢 408 条」降到「丢一小段」）
- 事后可查（§4.3）

### 7.2 不要把「落盘」委托给正在退化的模型

一期 §5.4 的设计是「助手在压缩前写下带着判断的摘要，进记忆」。**在全自动退化场景下这个
前提是反的**：触发压缩的时刻，模型正在输出 `好` / `做` / `我发`——**让一个正在打转的模型
做高质量总结，它写出来的东西不可信。**

所以本期的顺序要反过来：**要进记忆的内容由插件机械提炼**（读回被遮蔽区间自行摘要），
而不是先让模型写、再压缩。

## 八、误判控制

全自动意味着「用户没察觉就改了上下文」，所以误判的每一条代价都要有对应的抑制：

| 误判代价 | 抑制手段 | 状态 |
|---|---|---|
| 压掉了有用的上下文 | ~~只压相关区间~~ → 见 §8.1 | **不成立** |
| 用户不知道发生了什么 | 触发记录 + 用户可见提示（§7） | 成立 |
| 反复误触发 | 冷却期（待 §六.4 的复发数据） | 待数据 |
| 阈值定错 | 可重放数据 + 显性配置（§五） | 成立 |

### 8.1 「只压一小段」很可能是错的

`compactRegion` 接受区间，容易顺势推出「只压退化那一段，代价就小」。**这个推论有两个问题**：

1. **退化样本是散布的，不是集中的。**实测里重复率从 t10 持续到 t18，**每一轮都在 48%–83%**——
   碎片遍布整个退化期。要清除全部样本，区间就是 `[退化起点, 当前]`，在本次会话里等于一半的
   上下文，**这不叫「一小段」**。
2. **样本位置与「最近」高度重叠。**碎片是模型刚写下的，所以含样本的区间**同时含最近的用户
   消息与结论**。压它 = 丢掉最近这段对话。

**唯一可能让「小段」成立的机制**是近因效应——只有最近的样本有强影响，压掉最近 N 轮就够。
**但这是未验证的假设**（§六.2），不能拿它当抑制手段用。

**所以全自动当前的诚实状态是**：误判一次，就要付出「丢掉退化起点之后全部内容」的代价。
这比最初设想的贵得多——**在 §六.1 验证出更省的区间选择之前，它不足以支撑「全自动深压」**。

**「用户可见提示」的实测落点**（2026-09-29，SSiD dev / DSH 0.2.0-rc.1）：

用临时阈值（`repetitionThreshold: 0` + `consecutiveSteps: 1`）逼出一次真实触发，
会话日志里拿到三段证据：

```
EVENT   allostasis/degeneration
MESSAGE source.kind=plugin:dsh-allostasis  form=notice
        summary="推理退化 · turn 1 · 重复率 0%"
```

界面上则**分标签页不同**：**轨迹页能看到**「推理退化」，**对话页搜不到**。

这条修正推翻本文档先前按源码写下的判断。当时的依据是 `ui-chat` 的
`ContextBody.tsx:554-582` 与 `ContextInjectionRow.tsx:70-73`——那两处确实会把 `notice`
的 `summary` 画成折叠行上的一行（带 `data-context-summary` 锚点），**但实测表明它没有
出现在对话页**。源码里读到的渲染路径，与用户实际看到的界面不是一回事；这一条以实机为准。

把 form 从 `snapshot` 改成 `notice` 仍然成立：`ContextBody.tsx` 的 snapshot 分支给出的
`summary` 是 `null`（同文件 L568），而 `notice` 的定义是「一行刚发生了什么，行不展开时
就显示」（`llm/llm/src/message.ts:96-99`）。它至少让**轨迹页**有了那一行。

**结论**：「日志可审计 + 轨迹可查」这一档已经成立；**主动预警**（用户不切标签页就能看到）
仍需客户端半边或借悬浮球，**未做**。它不弹窗、不打断是有意的——一段一直存在的提醒会退化成
背景音，重演它要修的那个问题。
| `compactRegion` 调用 | **暂缓** | 区间选择未决，误判代价目前偏高（§8.1） |
| 标定阈值 | 二期后半 | 需要样本量 |
| LLM 自调 | 二期后半 | §5.2 的三条约束先落地 |

排查「模型在打转」时，触发记录与推理原文都在会话日志里，用
`dsh-session-forensics` 技能即可复现判定（§4.3 的可重放口径）。
